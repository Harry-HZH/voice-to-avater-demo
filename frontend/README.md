# Voice to Avatar — 前端（Expo + React Native）

面试题「Voice to Avatar」的 Web 前端。React Native（Expo SDK 57）+ react-native-web，
一套代码同时兼容手机浏览器和桌面浏览器（内容区限宽 640px 居中，左上角面包屑导航）。

**当前阶段：UI 框架 + 声音库 / 形象创作已接后端。**
**声音库**（`voice-to-avater-demo/backend`）里每个声音都能播放**真实的人声试听音源**，
并可用任意声音把任意文案真实合成出来；**候选形象与三视图**已接真实文生图 / image-to-image
（提交任务 → 轮询进度 → 取回真实图片）。创作（Creation）仍是 `src/data/` 的模拟数据。
后端不可用时全部自动回退到本地种子数据 + 本地推进器。

## 运行

```bash
# 1) 启动后端（声音库与真实音源都来自这里）
cd voice-to-avater-demo/backend
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python scripts/build_samples.py        # 首次：生成试听音源（约 1 点）
.venv/Scripts/python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 2) 启动前端
cd voice-to-avater-demo/frontend
npm install      # 首次
npm run web      # 浏览器打开 http://localhost:8082
```

后端地址通过 `frontend/.env` 的 `EXPO_PUBLIC_API_BASE_URL` 配置（默认 `http://localhost:8000`）。
**只跑前端也能用**：连不上后端时会回退到本地种子声音，只是没有真实音源。

其他平台：`npm run android` / `npm run ios`（需要 Expo Go 或开发构建）。
类型检查：`npm run typecheck`。

## 声音库与真实音源

原先 20 个声音的 `sample_url` 全是同一个占位音乐地址，且前端从未真正播放过它。
现在链路是完整的：

- **列表** `app/voices.tsx`：`loadVoices()` 走后端 `GET /api/voices`，语言筛选按实际数据生成，
  顶部显示「N 个真实音源已就绪」；点卡片上的播放键播放**真实人声**。
- **详情** `app/voice/[id].tsx`：播放该声音的真实音源；新增「用这个声音说一段话」——
  输入文案 → `POST /api/voices/{id}/preview` → 轮询 Job → 播放合成结果（真实 TTS）。
- **播放器** `src/lib/useSamplePlayer.ts`：同一时刻只播一个；音源未就绪时先等后端生成
  （后端返回 202 + 后台生成），就绪后再播，避免把 JSON 当音频放。
- **兜底**：任何一步失败都回退到本地 mock，并在界面上给出提示，而不是白屏或静默失败。

音源从哪来、怎么缓存、花多少费用，见 `backend/README.md`。

## 候选形象生成是「任务」：可以离开，再回来接着看

生成候选形象不是页面里的一个定时器，而是一条**写进任务中心、由后端执行的任务**：

- 点「生成候选图」→ 调 `POST /api/portraits` 提交一次**真实文生图**，拿到任务 id 并
  **把 id 写进 URL**（`?job=<id>`），任务中心立刻能看到这条任务与实时进度；
- 生成中可以直接离开（页面上的「去任务中心看进度 ›」），**进度在后端继续推进**；
- 在任务中心点这条流程（running 显示「继续这个流程 ›」）→ 回到 `/avatar/create/voice_001?job=<id>`，
  **进度接着走**，完成后自动进入候选页；
- 按任务状态决定落点：`queued/running` → 等待页，`succeeded` → 候选页（或补图任务 → 保存页），
  `failed` → 失败页（可重试）；
- 步骤行上的**取消**与**重试**都是真的：取消 → `POST /api/jobs/{id}/cancel`（后端停止收尾），
  重试 → `POST /api/jobs/{id}/retry`（**已生成成功的候选图会复用，只补失败的**）。

数据层在 `src/data/portrait.ts`：

- **后端优先**：提交 + 每 1.5s 轮询 `GET /api/jobs/{id}`，把后端任务原样写进本地列表，
  所以页面照旧只读本地列表（`getJob` / `jobs` + `subscribeData`）；
- **本地兜底**：后端没起或没配 key 时退回 `src/data/mock.ts` 的本地推进器，纯前端 demo 照样能演示；
- 打开任务中心时会用 `GET /api/jobs` 对齐一次，**刷新页面后之前生成的形象任务还能点回去看候选**；
- 自动化脚本要反复点「生成候选图」，不能每次真花钱：浏览器里放一个开关
  （URL `?portraits=mock` 或 localStorage `vta.portraitMode = "mock"`）可强制走本地演示。

## 任务中心按流程展示，不按任务平铺

任务是平铺的（后端只有 Job 一种东西），但用户眼里它们是一个个**流程**：出候选图 →
补三视图 → 保存角色 → 写台词 → 出片，说的都是同一个角色。所以任务中心展示的是流程卡
（`src/data/flows.ts` 现算聚合，`src/components/FlowCard.tsx` 渲染）：

- **创建角色阶段**：一条候选任务（`kind != "views"`）牵头，三视图任务按 `input.source_job_id`
  挂回它；保存成功后角色的 `source_job_id` 反过来指向这条候选任务，流程就和角色绑上了。
  角色不在本地（换过浏览器）时，说话任务自带的 `source_job_id` 也能把它们并回同一条流程。
- **开口说话阶段**：speak 任务按 `input.avatar_id` 归组，每条台词一步；种子角色（没有创建流程）
  自成一条只有创作阶段的流程。
- **tts 试听任务不入中心**：那是声音库里的单次试听，结果当场就听了，不是需要跟踪进度的生成任务。
- **流程级状态**看卡头（进行中 / 需处理 / 已完成），**单步状态**看步骤行；整卡点击 = 继续这个流程
  （跳到第一个没跑完的步骤），步骤行点击 = 回到那一步。失败步骤带重试，进行中步骤可取消。
- 演示种子任务（`job_001`～`job_006`）已随之清理：任务中心只放真实使用产生的任务，
  不再有写死的假条目和用户的真流程混在一起。

## 形象图：真实图片 + 占位图二选一

`WatercolorPortrait` 现在接受一个可选的 `url`：

- 传了 `url`（后端生成的候选图 / 三视图）→ 直接渲染真实图片，按 `cover` 裁成方形，
  格子布局与占位图完全一致；
- 没传（本地 mock 数据、历史演示数据）→ 继续用水彩 SVG 占位图。

同一处代码同时支撑「真实后端」和「纯前端 demo」两种状态，所以列表、详情、编辑页、
任务卡缩略图都能直接显示真实形象。

## 生成完之后还能改人物：修改设定 + 重新生成候选

候选页的人物设定不是死数据，点卡片上的「修改」或下方「修改人物设定」打开弹窗：

- 可改**形象描述**（重新生成时的提示词）与**年龄段 / 性格 / 风格 / 人物简介**；
- 弹窗底部只有两个按钮，都靠右下角：**取消**（不保存）与**保存并重新生成**（沿用新设定重出 3 张候选图，回到等待页，任务状态可见）；
- 「换一批候选图」：不改设定，直接换一批。

设定按候选维护（3 张候选各有自己的设定，编辑的是当前选中的那一张），
保存后立刻反映到人物设定卡与保存页。

## 让角色开口说话（唯一的创作功能）

创作模块**只有一件事**：拿角色的脸 + 角色的音色，把一段台词说成视频。
之前那套「选创作类型（口播 / 介绍商品 / 纯自定义）→ 编排动画 → 上传参考图」的向导已经整个删掉，
原因很直接：它把「动画怎么运镜」这种连模型都执行不了的自由文本丢给用户填，
是把技术难题伪装成用户输入；而用户真正要的东西只有两样 —— 一张脸（形象已经做好了）和一句话。

- **入口**：角色卡片操作弹窗的「让 TA 说话」、角色详情页创作库的「新建」、
  任务中心里历史说话任务点回来。
- **页面**：`/avatar/[id]/create`，三态推进 —— **写台词 → 出片中 → 成片**，中间没有向导、没有类型选择。
- **前置条件**：角色必须有一张**真实**形象图（`views.front` 有值，或能追溯到 `source_job_id`）。
  种子角色的 `views.front` 是 `null` 占位图，上游没有可动的人像，所以会被拦住并引导去「去生成形象」——
  这件事必须在**合成台词之前**说清楚，而不是等用户花完钱才报错。

### 费用是这个页面的主角

| 环节 | 单价 | 一条 15 秒成片的量级 |
| --- | --- | --- |
| 试听（TTS，`fish-audio/text-to-speech`） | 约 1.5 点 / 条 | 1.5 点 |
| 出片（说话视频） | 20 点 / 秒（720p）、30 点 / 秒（1080p） | 300 点 |

两者差两个数量级，所以费用被设计成**逐步才知道得更准**，并且能不算就不算：

1. **敲字时**：按 4.5 字/秒粗估秒数，右侧实时显示「约 4 秒 · 80 点（估算）」，明确标出「估算」——
   不让用户把一个估数当成准数（`src/lib/cost.ts`，与后端 `settings.speak_points` 同一套公式）。
2. **试听后**：用后端量出的**真实秒数**覆盖估算值，同时「（估算）」消失、费用文案变为精确值。
3. **试听只要 1.5 点而出片是 20 点/秒**，所以「先听再出片」是省钱而不是流程冗余。
   试听过的音轨按 `sha1(voice_id + 台词)` 缓存在后端，出片时直接复用，不会把 TTS 买第二遍。
   **但没试听也能直接生成** —— 试听是可选的钱包保护，不是强制关卡。
4. 台词改动一个字，试听结果立刻失效并退回估算口径（`preview.script === script` 才认），
   否则就是拿着 A 段的秒数给 B 段报账。
5. 念出来超过 30 秒（`MAX_SECONDS`）时给出提示并禁用生成按钮——超限拦截在前后端各做一次，
   前端拦住是为了即时反馈，后端拦截才是真正的约束。

### 流程细节

- **写台词**：多行输入（上限 1000 字），字数与费用实时显示；空台词时试听与生成按钮都禁用。
- **画面比例**：竖屏 9:16 / 横屏 16:9 二选一，随任务提交给后端。
- **出片中**：显示真实阶段名与进度（`合成台词 → 让角色开口`），进度与阶段由后端透传，不做匀速假动画；
  可以离开页面，任务中心会一直显示进度，也能取消。
- **成片**：真实 `<video>` 播放（`VideoPlayer`）+ 可单独播放的台词音轨 + 标题输入 + 「保存到创作库」。
  成片没能缓存到本地时**如实说明**，不拿占位图假装有视频。
- **二次编辑**：创作详情页「改台词重新生成」→ 携带 `?edit=<creationId>` 回到创作台，
  台词与标题预填。注意它**停在写台词态**而不是结果态 —— 按钮就叫「改台词重新生成」，用户的意图是改台词。

### 数据模型

`Creation { id, avatar_id, type: "speak", title, script, created_at, updated_at, video_url?, voice_url?, cover_url?, job_id?, duration?, points? }`。

不再往任务中心补一条 `creation` 记录：成片本身就是一条后端 `speak` 任务，
再写一条只会在任务列表里出现两个说的是同一件事的条目。因此 `JobType` 里的 `creation` 也已整个删除。

## 用户产出持久化（存在后端，浏览器只是缓存）

`Avatar` 与创作库原本是纯内存的模块级数组，刷新就回到种子数据 ——
那样「创建形象 → 让它开口说话」只能在同一个会话里连着做完，第二天回来自己做的角色就不见了。

用户产出**存在后端 `/api/library`**（MongoDB / JSON 回退，见 backend `app/routers/library.py`），
启动时根布局会等 `ensureLibraryLoaded()` 把数据灌进内存再渲染：

| 集合 | 内容 |
| --- | --- |
| `created_avatars` | 用户新建的角色（完整文档） |
| `avatar_patches` | 对种子角色的修改（改名 / 补视图等） |
| `deleted_seed_avatars` | 被删掉的种子角色 id（种子在代码里删不掉，只记账） |
| `creations` | 创作库（花了几百点做出来的成片，丢了不可接受） |

localStorage 不再存业务数据（它是按 origin 隔离的，换地址/换设备就"丢"）；
只留 `vta.portraitMode = "mock"` 这种演示开关。老版本存在浏览器里的增量会在
首次启动时自动迁移进后端（`src/data/library.ts: migrateLegacy`），搬完即清 key。
后端不可用时降级为纯种子数据：页面照常跑，改动只活在本会话（控制台有警告）。

> 数据一致性：`absUrl()` 对**任何自带 scheme 的地址**（`http(s):` / `data:` / `blob:`）都原样返回，
> 只给后端相对路径补域名。少了这一步，内联图片会被拼成 `http://localhost:8000/data:image/png;base64,...`，
> 变成一个永远加载不出来的地址。

## 三视图（front / side / back）

形象支持正面、侧面、背面三个视图，用于转身、多角度对话等场景：

- **创建时补充**：选定正面候选图后，流程会询问「需要补充侧面和背面吗」，可选立即生成
  （有进度、可取消）或跳过；之后也能补上。
- **补图是真实 image-to-image**：调 `POST /api/portraits/views`，把选中的那张候选的
  上游产物地址作为参考图传进去，提示词只描述「换视角、保持五官发型服装一致」，
  所以侧面 / 背面还是同一个人，而不是「长得像的另一个人」。
  补图是**独立的一条任务**（`input.kind = "views"`），任务中心能看到、能点回来、
  能单独重试（已成功的视角复用，只补失败的）。
- **编辑角色信息页管理**：三视图区块展示各视图状态，缺失视图点击即可生成；
  同样是**真实 image-to-image** —— 创建时保存的形象会记住「这张正面图来自哪个任务、第几张」
  （`Avatar.source_job_id` / `source_index`），补图时带着这个来源提交，
  后端自己取出上游那张图当参考，前端不用碰 provider 地址。
  生成结果直接写回本地形象数据，返回详情页仍然保留。
  演示数据（没有真实来源任务）或后端不可用时，退回占位图 + 本地进度演示，页面上会说明。
- **数据模型**：`Avatar.views` 为 `Partial<Record<"front" | "side" | "back", string | null>>`，
  **键的存在即该视图已生成**，值为图片地址（本地演示数据为 null，用水彩占位图）。
  此字段替代了 INTERVIEW.md 参考格式中的 `image_url`（正面图即 `views.front`），特此说明。

## 角色卡片（AvatarCard / AvatarCardView）

完整人像撑满卡片（正方形人像按封面裁剪，上下溢出被卡片圆角裁掉），
**底部 30% 为加深蒙层**（`expo-linear-gradient` 渐变：透明 → 深色），
蒙层上展示名称、日期、声音胶囊与三视图完整度（如 `2/3 视图`，齐备显示对勾、缺失显示提醒）。
可视部分抽成 `AvatarCardView`（无交互），列表卡片 `AvatarCard` 给它包一层点击 + 操作弹窗，
编辑角色信息页的**卡片预览**复用同一份视图（随表单输入实时更新），避免两处样式分叉。

## 卡片操作弹窗（AvatarActionSheet）

点击角色卡片弹出占**屏幕 80% 高度**的 bottom sheet（复用通用 `BottomSheet`，**点击遮罩关闭**）：

- **查看生成内容** → Avatar 详情页（创作库、最近任务）；
- **让 TA 说话** → 创作台 `/avatar/[id]/create`（写一段台词，用 TA 的形象和音色说成视频）；
- **编辑角色信息** → 跳转独立页面 `/avatar/[id]/edit`（不再在弹窗内联编辑）；
- **删除角色**（红色，末位）→ `ConfirmSheet` 二次确认，自建角色直接移除、种子记删除标记，连带清创作记录。删除入口只在弹窗里 —— 详情页是「查看生成内容」的地方，不放危险操作。

## 状态处理（面试关注点）

- **加载**：声音列表骨架屏；生成中有进度条 + 真实阶段名 + 可取消（候选形象、三视图、说话视频）。
- **排队**：流程步骤行展示 queued 态（排队中），与 running 的真实进度、阶段名并列。
- **失败**：形象创建流程有失败卡片，展示错误码 + 原因 + 重试/返回修改；
  创作台把失败原因就地显示在台词框下方（不跳页），改一句台词就能重来；
  任务中心保留历史 failed 任务（含 speak 类型）及其重试入口 —— 说话任务的重试会**复用已合成好的音轨**，只重跑出片，不把 TTS 买第二遍。
- **空状态**：无声音、无 Avatar、无任务、无创作各有引导 + 主行动点
  （如创作库空态是「还没有创作，去让 TA 说第一句话」）。
- **前置条件说在前面**：角色没有真实形象图时，创作台直接拦住并引导去生成形象 ——
  而不是让用户写完台词、合成完音轨，才在出片那一步报错。
- **不该给数字的地方不给**：费用在试听前明确标注「估算」，试听后才换成后端量出的真实秒数；
  时长为空时 `describeCost` 返回「时长未知」而不是编一个数。
- **生成中可离开**：候选形象 / 三视图 / 说话视频都由**后端执行**，前端只轮询 `GET /api/jobs/{id}` 取进度；
  离开页面不打断生成，任务中心同样轮询显示进度。刷新后打开任务中心会 `hydrateJobs()` 从后端对齐，
  点流程卡即可**接着看**（进度不归零）。
- **生成完还能改**：候选页可修改人物设定并重新生成候选；成片可从创作详情页回去改台词重新生成。
- **不假装有产物**：成片没能缓存到本地时，创作台/创作详情页都如实说明，不拿占位图充当视频。

## 后端接入现状

- **声音库已接后端**（见上）。
- **候选形象 / 三视图已接后端**：`src/data/portrait.ts` 调 `POST /api/portraits` 与
  `POST /api/portraits/views` 建任务，随后轮询 `GET /api/jobs/{id}` 取进度与产物；
  后端连不上（`ApiError`）时自动回退 `src/data/mock.ts` 的本地定时器推进，页面无需改动。
  「重试」复用已成功图片、「换一批」清缓存整批重出，取消走 `POST /api/jobs/{id}/cancel`。
- **说话视频已接后端**：试听走 `POST /api/speak/preview`（真花钱，约 1.5 点），
  出片走 `POST /api/speak`，之后同样轮询任务。**这条链路没有本地兜底** ——
  候选形象可以退回水彩占位图演示，但视频没有「假装生成」的意义：
  一条假视频对用户毫无价值，还容易让人以为功能已经能用。所以后端不可用时直接如实报错。

## 后续可做

- 音色目录：后端已提供 `GET /api/catalog/voices`（1000+ 真实音色）与 `POST /api/voices/import`，
  前端还没做「浏览目录 → 加入我的声音库」的界面。
- 编辑角色信息保存对应 `PATCH /avatars/{id}`；当前直接改内存对象并 PUT 到 `/api/library/avatar-patches/{id}`。
- 创作库目前只有一条时间线，支持删除（创作详情页 + Avatar 详情页确认弹窗）；重命名 / 搜索还没有。
- 1080p：后端已支持（30 点/秒），前端还没给清晰度开关（现在固定 720p）。
- 多语言台词：现在按 4.5 字/秒估秒数只对中文口播成立，英文台词要换系数。
