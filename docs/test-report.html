4. 测试方法说明

后端测试全部通过 conftest 的假上游（fake_provider）驱动：可精确控制上游返回成功/失败/超时， 并统计调用次数——「取消后零新增上游调用」「TTS 只买一次」这类费用相关断言因此可被严格验证，而不依赖真实扣点。 e2e 默认走演示模式（vta.portraitMode=mock）做零成本回归；真实链路由带标注的 *-real.mjs 脚本单独验证。

5. 已知边界（非缺陷，属明确取舍）

  • 上游取消不可达：已提交给 ThankYou 的生成请求无法撤回，取消只保证本地立即停止等待、不再下载、状态不再被覆盖；上游是否扣点取决于其计费时点。
  • 后端重启孤儿任务：running 中重启后端，任务无人接管（需任务队列才能可靠恢复，见 README「没做的部分」）；用户可「取消 → 重试」，音轨有缓存时重试只花出片的钱。
  • 前端任务列表是内存态：刷新丢失，靠打开任务中心时与后端对齐恢复——后端是唯一真源，这是有意设计。
